# Decisions Register

Append-only. To reverse a decision, add a new row that supersedes it — don't edit or remove existing rows.

| # | Scope | Decision | Choice | Rationale |
| --- | --- | --- | --- | --- |
| D001 | architecture | SmartSpectra data contract correction | Drop `gazeDisp`, `reading`, `regularity`, `blinkRate`-as-rate from contract. Normalize `conf` from 0-100 to 0-1 at agent. All physio fields nullable. Derive blink rate from binary `DetectionStatus` events. | Verified against real Presage SDK docs: `gazeDisp` and `reading` are not SmartSpectra metrics, blink rate is binary `DetectionStatus`, `regularity` does not exist, `conf` is 0-100 not 0-1. Building on phantom signals would break both lanes. |
| D002 | architecture | Zone-out classifier rewrite | Replace `gazeDisp` + `reading` rule with: blink-rate-change (derived, > baseline × 1.4) + head stillness (landmark centroid variance over 5s window) + HRV/EDA arousal drop + study-app context + not-talking, sustained 90 seconds | Original rule used signals that don't exist in the SDK. Replacement uses only real SDK signals. Each adds detection value: blink rate correlates with mind-wandering, head stillness indicates disengagement, HRV/EDA shows parasympathetic shift. |
| D003 | architecture | Monorepo structure | pnpm workspaces + turborepo with `packages/shared`, `apps/agent`, `apps/api`, `apps/web` | Shared `types.ts` via `@flow/shared` prevents contract drift between agent, API, and frontend. Turborepo parallelizes builds. pnpm is faster than npm for monorepo installs. |
| D004 | infrastructure | Deployment architecture | Single Vultr VM with Docker + Caddy at tryflow.study for API + frontend. Agent runs on Windows laptop. No Vercel. | Vultr is a sponsor track. Eliminates Vercel deploy complexity and mixed-content `ws://localhost` issues. One Dockerfile, one deploy target. |
| D005 | architecture | Database choice and features | Tiger Cloud managed TimescaleDB with hypertable, continuous aggregates (1-min and 5-min), compression policy, gapfill, and retention policy | Tiger Cloud is a sponsor track. 20Hz physio data is textbook hypertable workload. Advanced features show technical depth to judges. Continuous aggregates serve dashboard without recomputation. |
| D006 | architecture | Gemini integration surfaces | Three surfaces: session narrative (on session end), cross-session insights (per-card on insights page), app categorization (few-shot + cache-first). Direct Gemini API, no Backboard. | Maximizes sponsor integration value with three distinct touchpoints. App categorization uses few-shot prompt with exact category enum for consistency, cached per app title. Batch unseen titles every 30s. |
| D007 | architecture | Voice and audio strategy | ElevenLabs via server-side Fastify proxy (`/v1/speak`), pre-cached fallback audio files for fixed nudge lines, mute toggle in UI | Key never reaches browser. Pre-cached files ensure demo survives API hiccup. Mute respects user preference for studying without audio interruptions. |
| D008 | architecture | UI design language | Notion-esque: minimal, expressive typography, clean whitespace, warm neutral palette. Not clinical health dashboard or dark developer tool. | UX and Design is a hackathon judging criterion. User explicitly wants innovative, productive feel. Notion is the reference point for clean, readable data presentation. |
| D009 | process | Project orchestration | Dropped gsd-pi (external autonomous-agent CLI) entirely — Claude now drives implementation directly against these docs, with plain git commits under the user's own identity (no co-author attribution). | gsd-pi's dynamic model routing and auto-mode repeatedly wedged on internal DB/artifact-drift bugs across two separate incidents, requiring destructive DB restores to unblock. Not worth the friction mid-hackathon; the project's actual value is the markdown contract (this file, REQUIREMENTS.md, ROADMAP.md), which doesn't need a bespoke runtime to stay useful. |
